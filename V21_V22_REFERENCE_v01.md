# ORAC LUT V21 (IDL) and V22 (Python): definitive reference releases

Status 2026-10-12: **final**.  The IDL-to-Python translation is complete.  The
original single-precision IDL V21 is the definitive IDL reference; the
single-precision Python V22 is the definitive Python reference.  For the three
standard Terra MODIS products, V22 is **bitwise identical to V21 in all 52
NetCDF variables**.  V23 is the next development version.

## What V21 and V22 are

| | V21 (IDL) | V22 (Python) |
|---|---|---|
| Generator | `create_orac_lut/create_orac_cloud_lut.pro` and the IDL source set of the manifest (original `call_disort.pro`) | `create_orac_luts.py` and `src/oraclut` (IDL-mirroring port) |
| Release manifest | `releases/idl_lut_v21_single.release` (161 entries: IDL sources, DLMs, inputs, Intel run time, products) | `releases/lut_v22_single-r2.release` (sha256 `33c7f64c638345a0...`, 58 entries) |
| Git tag | `idl-lut-v21` | `lut-code-v22.4` (commit `c591d2b`; validation record `f9b0b3b`) |
| CODE_VERSION | — | `lut-code-v22.4`, scientific configuration `v22-idl-single` |
| DISORT | `create_orac_lut/disort2/src/DISORTtoIDL.so` (ifort -O3, sha256 `59307e42604ca0f7...`), single precision | the same binary, called from Python with IDL's array memory layout |
| Streams / moments | NSTR 60, NMom 1000 | NSTR 60, NMom 1000 |
| Grids | `liquid-water-cloud.lut` (sha256 `5b233f8f...`), `ice-cloud.lut` (`3142e32f...`): the original V2.1 coarse grids, preserved as `*_v01.lut` | the same files |
| Mie / Baum | `mie_dlm_single.so` (ifort) / `read_baum.pro` | gfortran build of the same `mieint.f` (bitwise-equivalent results) / IDL-arithmetic Baum interpolation |

The original single-precision DISORT behaviour, including its numerical
imperfections (ill-conditioned SZA 80 direct-beam calls, negative reflectances
and transmissions), is **intentionally reproduced, not corrected**.

## Equivalence

* All 52 variables of each V22 product are byte-identical to the V21 product
  (dimensions, coordinates, channel identifiers, optical properties, F0, all
  nine RT operators, every negative value); only the release launcher's
  provenance attributes are added.  ORAC's interpolated coefficients,
  radiances and Jacobians are therefore identical.
  Check: `python validation/v21_v22_terra_modis/v21_v22_single/compare_full_luts.py`.
* All 90 DISORT calls captured inside IDL (four compact cases) are reproduced
  bitwise in every argument and output; regression tests
  `tests/test_v21_single_reproduction.py` with compact reference data in
  `tests/data/v21_idl_single/`.
* The IDL arithmetic V22 reproduces (`src/oraclut/idl_math.py`, `idl_mirror`):
  DISORT array data 8 bytes past a 16-byte boundary and its in-place UTAU/SSALB
  changes; FLOAT `!DTOR`/`!pi`; glibc `cosf`, `exp`, `pow`, `acos`; FLOAT `EXP`
  as the rounded DOUBLE `exp`; integer powers by repeated squaring;
  `quadrature.pro` Newton nodes; FLOAT literals and wavenumbers; FLTARR storage;
  `INTERPOL` in the operands' type; `INTERPOLATE` with FLOAT locations and
  double arithmetic; the writer's `/100`.

## Reproducing the releases

Both releases read the working input definitions.  Until V23 changes them,
run from the current tree; afterwards (or to be certain), run from the tag:

    git worktree add ../oraclut-v22 lut-code-v22.4     # or idl-lut-v21

**V21 (IDL)**, on a host with IDL 8.9 and the Intel 2022 run time:

    cd create_orac_lut && bash terra_modis_run          # writes luts/terra_modis_cloud/
    python scripts/check_release_manifest.py releases/idl_lut_v21_single.release

**V22 (Python)**, on a SLURM node (one CPU, ~4.6 h per product):

    bash scripts/submit_v22_single.sh                    # -> staging/lut_v22_single-r2/
    # or directly:
    ORAC_LUT_RELEASE_MANIFEST=lut_v22_single-r2.release ORAC_LUT_DISORT_PRECISION=single \
    ORAC_LUT_DISORT_SP_KERNEL=intel_dlm \
    python create_orac_luts_release_v04.py runs/terra_modis_cloud_liquid-water_240_v22_single-r2.run

The launcher refuses to run unless every sealed file matches the manifest and
single precision with the Intel kernel is selected.  Then compare with
`ORAC_LUT_V22_CANDIDATES=staging/lut_v22_single-r2 python validation/v21_v22_terra_modis/v21_v22_single/compare_full_luts.py`.

Dependencies outside Git (`releases/lut_v22_single-r2.dependencies`, checked
by `scripts/check_release_manifest.py`): the third-party Baum table
`create_orac_lut/input_files/baum/AggregateSolidColumns_SeverelyRough_AllWavelengths_FullPhaseMatrix.nc`
(git-ignored; keep it in place), the Intel 2022.1.0 run time, glibc 2.36 and the
conda environment (`releases/lut_v22_single-r2.environment.txt`).  Verified
copies of the external binaries are kept in `archive/lut_v22_dependencies/`
(local, not in Git).

## Other releases and history

`releases/README.md` lists every manifest.  Superseded or experimental:
`lut_v22.release` (historical gfortran V22, tag `lut-code-v22.1`),
`lut_v22_single.release` (corrected V22 revision 1), `lut_v22_double.release`
and `idl_lut_v21_double.release` (suspended double-precision work,
`DOUBLE_PRECISION_BASELINE.md`).  They remain sealed and verifiable; none is a
reference.

The detailed V21/V22 investigation (reports, diagnostics, captures,
intermediate results) was removed from the working tree on 2026-10-12 and is
preserved in Git: `git show f9b0b3b:validation/v21_v22_terra_modis/REPORT_single_precision_equivalence.md`,
or check out `lut-code-v22.4`/`f9b0b3b`.  Untracked development material
(IDL capture files, SLURM logs, staging records) is in
`archive/v21_v22_development_untracked_20261012.tar.xz` (local, verified;
file list beside it).

## Next: V23

V23 is the next development version.  It will introduce the revised LUT grid
deliberately: the active definitions keep their names
(`liquid-water-cloud.lut`, `ice-cloud.lut`), SourceVault preserves the V21/V22
grids (`*_v01.lut`), and V21/V22 remain reproducible from their tags.  V23 is
not started here.
